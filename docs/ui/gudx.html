Gudx & Binding

네임스페이스 Going.UI.Gudx / Going.UI.Bindings — .gudx XML 마크업과 선언적 바인딩

1. 개요 — .gudx 란

.gudx는 화면(GoDesign 객체 그래프)을 그대로 담는 XML 마크업 포맷입니다. 태그는 컨트롤 클래스 이름, 속성은 컨트롤의 속성 이름을 PascalCase 그대로 씁니다. 코드 생성 도구 없이 라이브러리만으로 파일을 읽어 화면을 띄울 수 있고, 데이터 연결은 속성 값에 적는 {path} 바인딩 식으로 처리합니다.

변환은 GoGudxConverter가 리플렉션으로 수행합니다. 포함은 명시적입니다 — 스칼라 속성은 [GoProperty] 계열이 붙은 것만 XML 속성이 되고, 자식은 [GoChild*] 마커가 붙은 속성만 자식 엘리먼트가 됩니다. 마커가 없으면 직렬화되지 않습니다.

파일 구성 — 두 가지를 모두 지원합니다.
단일 파일: 한 개의 .gudx에 <GoDesign> 전체(페이지 포함)를 담고 GoGudxConverter.ReadGoDesign(XElement)으로 읽습니다.
Master 분할: Master.gudx가 디자인 속성·테마·바(bar)·리소스 참조와 <GoPageRef File="Pages/Xxx.gudx"/> 포인터만 갖고, 페이지/윈도우는 별도 파일에 둡니다. GoDesign.DeserializeGudx(masterPath)가 참조를 해석해 한 번에 읽습니다.

런타임 로드 경로
구성 읽기 쓰기
단일 파일 / 메모리 GoGudxConverter.ReadGoDesign(XElement) GoGudxConverter.WriteGoDesign(GoDesign)
Master 분할 (파일 세트) GoDesign.DeserializeGudx(masterPath) GoDesign.SerializeGudx(masterPath)
컨트롤 하나 (부분) GoGudxConverter.DeserializeControl(xml) GoGudxConverter.SerializeControl(control)

읽은 GoDesign을 GoViewWindow.Design에 대입하고, 페이지를 지정한 뒤 바인딩을 연결하면 끝입니다. 

using System.Xml.Linq;
using Going.UI.Design;
using Going.UI.Gudx;
using Going.UI.OpenTK.Windows;

var hub = new AppHub();
var design = GoGudxConverter.ReadGoDesign(XElement.Load("ui/Main.gudx"))
             ?? throw new InvalidOperationException("gudx 파싱 실패");

using var win = new MainWindow(design, hub);
win.Run();

public sealed class MainWindow : GoViewWindow
{
    private readonly AppHub hub;

    public MainWindow(GoDesign design, AppHub hub)
        : base(1024, 600, WindowBorder.Hidden)
    {
        Design = design;
        this.hub = hub;
    }

    protected override void OnLoad()
    {
        base.OnLoad();
        Design.SetPage("Main");
        Design.WireBindings(hub);   // 마크업의 {…} 식을 hub에 연결
    }
}

.gudx 화면을 시각적으로 설계하고 검증하려면 Going Library 위에 만들어진 HMI 통합 개발 도구 Senvas를 사용하세요 — 라이브러리 자체는 위 예제처럼 독립적으로 동작합니다.

2. 마크업 문법
기본 규칙
규칙 내용
루트 디자인 전체는 <GoDesign>, 페이지 파일은 <GoPage>, 윈도우 파일은 <GoWindow>가 루트
태그 컨트롤 클래스 이름 그대로 (PascalCase). 제네릭은 Type<arg> → Type_arg (예: <GoInputNumber_double>)
속성 [GoProperty] 계열이 붙은 스칼라 속성만 XML 속성으로 출력 (P1). 이름은 속성 이름 그대로
Bounds Bounds="Left,Top,Right,Bottom" — SKRect 원시값이라 Width/Height가 아닌 우하단 좌표입니다. Width/Height는 [JsonIgnore] 런타임 별칭이라 직렬화되지 않습니다
Margin / Padding Margin="L,T,R,B" 형식
컬렉션 모든 컬렉션은 속성 이름 그룹 엘리먼트 안에 들어갑니다 (<Childrens>, <Menus>, <TabPages>, <Series> …). v1.2.1부터의 XAML 스타일 규칙이며, 빈 컬렉션은 그룹 자체가 생략됩니다
Cell 셀 인덱스 컨테이너의 자식에 붙는 attached 속성. Cell="col,row" 또는 병합 시 Cell="col,row,colSpan,rowSpan"
크기 문자열 Columns/Rows/Size 등: "50%"(남은 공간의 %) · "100px"(고정) · "*"(미지정 % 잔여 균등 분배). 단위 없는 "100"은 지원하지 않습니다
패턴 (P1~P5 / B1 / B2)

변환기는 속성에 붙은 마커 어트리뷰트 타입으로 처리 방식을 결정합니다. 아래 7가지가 전부입니다.

패턴 마커 XML 형태
P1 [GoProperty] 계열 엘리먼트의 XML 속성 — <GoButton Text="Hello" FontSize="14"/>
P2 [GoChildList] List<T> where T : IGoControl → <Childrens> 그룹 + 컨트롤 클래스명 자식
P3 [GoChildCells] 셀 인덱스 컬렉션 → 그룹 + 자식마다 Cell="col,row" (GoTableLayoutPanel / GoGridLayoutPanel)
P4 [GoChildWrappers] IGoControl이 아닌 래퍼 리스트 → 그룹 + 래퍼 클래스명 자식 (<Menus><GoMenuItem/>, <TabPages><GoTabPage>, <Series>, <Steps> …)
P5 [GoChildMap] Dictionary<string, T> → 그룹 + <T Name="key" …/> (GoDesign.Pages, GoDesign.Windows)
B1 [GoChildSingle] 단일 자식 객체 → 속성 이름이 태그 (<TitleBar> <LeftSideBar> <RightSideBar> <Footer>). [GudxTagName]으로 태그 변경 (CustomTheme → <Theme>)
B2 [GoChildResource] 외부 파일 참조 → <TagName Name="…" File="…"/>. 바이트는 인라인(base64)하지 않고 디스크에 둡니다 (<Images>, <Fonts>)
Master.gudx 예
<GoDesign Name="TempControlSystem" DesignWidth="1024" DesignHeight="600"
          UseTitleBar="true" UseLeftSideBar="false" BarColor="Base2">

  <!-- B1: 속성 이름이 곧 태그 -->
  <TitleBar BarSize="50" FontName="나눔고딕" Bounds="0,0,1024,50">
    <Childrens>                             <!-- P2 그룹 -->
      <GoTableLayoutPanel Columns="220px,100%,380px" Rows="100%" Dock="Fill">
        <Childrens>                         <!-- P3 그룹 -->
          <GoNavigator Direction="Horizon" Cell="1,0" Dock="Fill">
            <Menus>                         <!-- P4 그룹 -->
              <GoMenuItem Text="Dashboard" PageName="MonitoringPage" />
              <GoMenuItem Text="Logs"      PageName="LogPage" />
            </Menus>
          </GoNavigator>
        </Childrens>
      </GoTableLayoutPanel>
    </Childrens>
  </TitleBar>

  <!-- B1 + [GudxTagName("Theme")] -->
  <Theme Dark="true" Fore="#FFE0EAF0" Back="#FF1A2530" Point="#FF4FC3F7" Corner="5" />

  <!-- B2: 외부 리소스 (바이트는 디스크에) -->
  <Images><Image Name="logo" File="resources/logo.png"/></Images>
  <Fonts><Font Name="Pretendard" File="resources/fonts/Pretendard.ttf"/></Fonts>

  <!-- Master 분할: 페이지는 별도 .gudx 파일 -->
  <Pages>
    <GoPageRef File="Pages/MonitoringPage.gudx" />
    <GoPageRef File="Pages/LogPage.gudx" />
  </Pages>
</GoDesign>

단일 파일 구성에서는 <Pages> 안에 <GoPageRef/> 대신 <GoPage Name="…">를 직접 넣습니다(P5). Master 분할 모드에서는 <Pages>/<Windows> 자식으로 <GoPageRef>/<GoWindowRef>만 허용됩니다.

3. 선언적 바인딩

속성 값 전체를 {…}로 쓰면 리터럴 대신 바인딩 식으로 해석됩니다. 역직렬화 시점에는 식이 보류 상태로 보관되고, GoDesign.WireBindings(root)를 한 번 호출하면 모든 페이지·윈도우·바 트리를 순회하며 root 기준 경로로 컴파일해 실제 바인딩으로 전환합니다. 경로는 wire 시점에 Expression으로 1회 컴파일 후 캐시되고, 값은 매 프레임(FireUpdate 펌프)마다 읽힙니다.

식 방향 설명
{Path.To.Member} 양방향 / 단방향 경로 말단이 settable이면 양방향, 아니면 단방향
{Path.To.Member:F1} 단방향 IFormattable.ToString(fmt) 결과를 표시. 포맷이 붙으면 역변환 불가라 항상 단방향
{{ — 리터럴 중괄호 escape (바인딩으로 판정하지 않음)

값이 {로 시작해 }로 끝나고 {{ escape가 아닐 때만 바인딩입니다. 그 외에는 전부 리터럴입니다. 재직렬화 시 원본 식이 그대로 보존되므로 라운드트립해도 리터럴로 굳지 않습니다.

컴포넌트 — <GoComponent> / <Param>

파라미터를 받는 재사용 마크업 모듈입니다. 정의는 <Components> 그룹에 모아 두며(페이지보다 먼저 레지스트리에 등록됨), 사용처는 컴포넌트 이름을 새 태그처럼 씁니다. 파라미터는 리터럴(Title="펌프 A") 또는 바깥 바인딩(motor="{PumpA}")으로 넘깁니다. <Param type="…">의 타입이 내부 경로({motor.Rpm})를 타입 안전하게 컴파일하는 다리 역할을 합니다 — string/int/double 등 별칭과 로드된 어셈블리의 클래스 simple name을 인식합니다. 인스턴스는 GoComponentInstance(컨테이너)로 역직렬화되므로 Bounds·Dock 등 기존 레이아웃을 그대로 씁니다.

컬렉션 반복 — GoItemList + <ItemTemplate>

Items="{Logs}"로 컬렉션을 바인딩하고 <ItemTemplate> 트리를 아이템마다 복제해 렌더합니다. 각 행은 그 아이템 객체를 root로 wire되므로 {Message} 같은 평면 경로가 아이템 멤버에 직접 닿습니다. 아이템 타입은 런타임 추론이라 type 선언이 필요 없습니다. ObservableList의 Changed 또는 개수 변화가 감지되면 행을 전량 재생성합니다. 직렬화에는 Items 식과 <ItemTemplate>만 남고 생성된 행은 출력되지 않습니다. 

<GoDesign>

  <!-- 재사용 컴포넌트 정의: motor(MotorVM) 하나를 받아 내부에서 바인딩 -->
  <Components>
    <GoComponent name="MotorCard">
      <Param name="motor" type="MotorVM"/>
      <GoBoxPanel Bounds="0,0,340,64" BoxColor="Base2" BorderColor="Base3"><Childrens>
        <GoLabel Text="{motor.Name}"   Bounds="12,8,210,36"  FontSize="15"/>
        <GoLabel Text="{motor.Rpm:F0}" Bounds="210,8,330,56" FontSize="26" TextColor="Point"/>
      </Childrens></GoBoxPanel>
    </GoComponent>
  </Components>

  <Pages>
    <GoPage Name="Main" BackColor="Back"><Childrens>

      <!-- 선언적 바인딩: 허브 멤버에 직접 -->
      <GoLabel Text="{PlantStatus}" Bounds="12,10,348,44" FontSize="20" TextColor="Point"/>

      <!-- 컴포넌트 인스턴스: 각각 다른 모터를 바인딩 -->
      <MotorCard motor="{PumpA}" Bounds="10,52,350,116"/>
      <MotorCard motor="{PumpB}" Bounds="10,124,350,188"/>

      <!-- 컬렉션을 ItemTemplate으로 반복 -->
      <GoItemList Items="{Logs}" ItemHeight="26" Bounds="10,226,350,458">
        <ItemTemplate>
          <GoBoxPanel Bounds="0,0,340,26" BoxColor="Base1"><Childrens>
            <GoLabel Text="{Message}" Bounds="10,3,330,24" FontSize="12"/>
          </Childrens></GoBoxPanel>
        </ItemTemplate>
      </GoItemList>

    </Childrens></GoPage>
  </Pages>
</GoDesign>

위 마크업의 {PlantStatus}·{PumpA}·{Logs}는 WireBindings(hub)에 넘긴 단일 컨텍스트 객체의 멤버입니다. 

public sealed class MotorVM
{
    public string Name { get; set; } = "";
    public double Rpm  { get; set; }
}

public sealed class LogVM { public string Message { get; set; } = ""; }

/// 마크업의 모든 {…} 경로가 이 객체에서 출발한다.
public sealed class AppHub
{
    public string PlantStatus { get; set; } = "RUN";
    public MotorVM PumpA { get; } = new() { Name = "펌프 A", Rpm = 1450 };
    public MotorVM PumpB { get; } = new() { Name = "펌프 B", Rpm = 980 };
    public ObservableList<LogVM> Logs { get; } = new();
}

1차 한계

  • 문자열 보간("속도: {x} m/s") 미지원 — 속성 값 전체가 하나의 식이어야 합니다
  • 일반 속성으로의 컬렉션/명령 바인딩 미지원 (컬렉션은 GoItemList + <ItemTemplate> 사용)
  • GoSwitchPanel / GoTabControl 내부 컨트롤은 아직 wire 대상이 아닙니다
  • 컴포넌트: 슬롯/자식 투영, 컴포넌트 이벤트·상태, 자동 fill 미지원
  • GoItemList: diff 부분 갱신, 가변 행 높이, 명명 컴포넌트 ItemTemplate 참조, 선택/가상화 미지원
4. 코드 바인딩

마크업 없이 코드로 직접 바인딩할 수도 있습니다. 선언적 바인딩도 결국 같은 펌프 위에서 동작합니다 — 매 FireUpdate에 양쪽을 폴링해 동기화하므로 이벤트 구독이 필요 없습니다. 컨트롤이 Dispose되면 자동으로 해제되고, Unbind / UnbindAll로 명시 해제할 수 있습니다. 

using Going.UI.Bindings;

// 단방향 — 소스 → 컨트롤
lblRpm.Bind(c => c.Text, () => hub.Motor.Rpm.ToString("F0"));

// 양방향 — setter를 주면 컨트롤 변경도 소스로 흐른다
sldSpeed.Bind(c => c.Value, () => hub.Motor.Target, v => hub.Motor.Target = v);

// 명령(command) 바인딩 — setter 후 getter 반영이 늦는 통신 속성용
swPower.Bind(c => c.OnOff, () => hub.Power, v => hub.Power = v, timeout: 500);

// 해제
sldSpeed.Unbind(c => c.Value);
lblRpm.UnbindAll();

조작 중 억제 — GoControl.IsBindingSuppressed(protected internal virtual)가 true인 동안 해당 컨트롤의 펌프가 정지합니다. 사용자가 조작 중일 때 소스 값이 컨트롤을 덮어쓰는 것을 막고, 조작이 끝나면 컨트롤 값을 소스로 1회 flush합니다. GoSlider·GoRangeSlider·GoKnob·GoOnOff가 이 플래그를 재정의합니다.

명령 바인딩 — timeout 오버로드는 setter 호출 후 getter가 같은 값에 도달하거나 timeout이 지날 때까지 이전 getter 값으로 컨트롤을 되돌리지 않습니다. 통신 ack 지연이 있는 속성에서 값이 깜빡이는 것을 막습니다.

5. API
public static class GoGudxConverter
GoControl 객체 그래프 ↔ Gudx XML 변환기. 리플렉션 기반 — 태그는 컨트롤 클래스 이름, 속성은 [GoProperty] 스칼라, 자식은 [GoChild*] 마킹 속성.
Methods
stringSerializeControl(IGoControl control)컨트롤 하나를 XML 문자열로 직렬화
IGoControlDeserializeControl(string xml)XML 문자열에서 컨트롤 하나를 역직렬화
XElementWriteAny(object obj, string? explicitTagName = null, ISet<string>? skipChildren = null)IGoControl이 아닌 루트(GoDesign 등) 포함 임의 객체를 XElement로 직렬화. 태그는 런타임 타입에서 유도하며 explicitTagName으로 재지정
XElementWriteGoDesign(GoDesign design)GoDesign을 XElement로 직렬화 (WriteAny 편의 래퍼)
GoDesign?ReadGoDesign(XElement elem)XElement에서 GoDesign 역직렬화. 루트 태그가 GoDesign이 아니면 null. <Components>를 페이지보다 먼저 등록
voidSerializeGoDesignToFiles(GoDesign d, string masterPath)Master + Pages/*.gudx + Windows/*.gudx + resources 파일 세트로 저장. 하위 폴더를 정리 후 재기록해 디스크와 동기화
GoDesign?DeserializeGoDesignFromFiles(string masterPath)Master.gudx에서 GoPageRef/GoWindowRef 참조와 Images/Fonts 리소스를 해석해 로드. 파일이 없으면 null
Remarks
고수준 진입점은 GoDesign.SerializeGudx(masterPath) / GoDesign.DeserializeGudx(masterPath)이며, 내부적으로 위 파일 세트 메서드를 호출합니다.
public static class GoControlBindingExtensions
GoControl 바인딩 확장 메서드. 매 FireUpdate에 양쪽을 폴링해 동기화하며 이벤트 의존성이 없습니다.
Extension Methods
voidBind<TC,TV>where TC : GoControl(this TC ctrl, Expression<Func<TC,TV>> ctrlProp, Func<TV> getter)단방향 바인딩. 매 FireUpdate에 소스 → 컨트롤로 값이 흐릅니다
voidBind<TC,TV>where TC : GoControl(this TC ctrl, Expression<Func<TC,TV>> ctrlProp, Func<TV> getter, Action<TV> setter)양방향 바인딩. 소스 → 컨트롤은 매 FireUpdate, 컨트롤 → 소스는 값 변경 감지 시
voidBind<TC,TV>where TC : GoControl(this TC ctrl, Expression<Func<TC,TV>> ctrlProp, Func<TV> getter, Action<TV> setter, int timeout = 500)명령 바인딩. setter 호출 후 getter가 같은 값에 도달하거나 timeout이 지날 때까지 이전 값으로 되돌리지 않습니다
voidUnbind<TC,TV>where TC : GoControl(this TC ctrl, Expression<Func<TC,TV>> ctrlProp)지정한 속성의 바인딩을 해제
voidUnbindAll(this GoControl ctrl)컨트롤의 모든 바인딩을 해제
Remarks
ctrlProp는 단순 속성 접근(c => c.Value)이어야 합니다. 필드·메서드·복합 식이면 ArgumentException. 같은 속성에 다시 Bind하면 기존 바인딩을 교체합니다(마지막 승).
public static class GudxBinder
컨트롤 트리를 재귀 순회하며 보류 바인딩을 root 기준 실제 바인딩으로 연결. GoDesign.WireBindings의 구현부입니다.
Methods
